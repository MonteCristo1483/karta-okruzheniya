# Бэклог идей (не текущая очередь)

Здесь живут продуктовые идеи, которые обсуждались, но не входят в текущую
работу. Ни одна строка отсюда не запускается в код без отдельного решения
владельца и брифа.

Дата заведения: 2026-11-24.

## Визуал и «фишка»

- **Диорама вокруг выбранного дома.** Ограниченный радиус, высокий наклон,
  туман по краям, мягкий свет, минимум подписей — «снежный шар» с домом
  в центре. Без нового движка, в текущем MapLibre.
- **Открытка дома.** Статичный стилизованный рендер (диорама) для шаринга
  в мессенджер и как OG-превью. Главный кандидат в вирусную фишку: люди
  пересылают картинку, а не интерактивную 3D-сцену.
- **Плавный 2D→3D без щелчка.** Дома «вырастают» на отрезке зумов вместо
  мгновенной подмены. Часть LOD-работы.
- **Игрушечная палитра сцены.** Тёплые крыши, мягкие тени, меньше UI-шума.
  В рамках текущего движка, без новых зависимостей.

## Данные и слои

- **Поток воздуха / роза ветров от комбинатов и магистралей.** Отдельный
  custom-слой: заранее посчитанное поле, анимация частиц. Нужны источники
  выбросов, климатология ветра и модель рассеивания — сначала данные,
  потом рендер. Не «реальное время» и не CFD.
- **Год постройки по всей Москве.** Сейчас 0,6% покрытия: импорт делался
  только по Пресне. Требует прогона реестра + паспортов по всем домам.
- **Материал стен, серия, этажность** — из тех же паспортов, если решим
  показывать.
- **Остановки наземного транспорта** как слой (данные есть в OSM частично).

## Продукт

- **Возврат OG-превью на каждый дом** — требует динамического хостинга или
  edge-функции; после решения по инфраструктуре.
- **Сохранённые подборки домов** — требует аккаунтов и бэкенда.
- **Сравнение двух домов** — интерфейс поверх готовых данных, без бэкенда.
- **Метрики использования** (что смотрят, где бросают) — для проверки
  спроса, требует аналитики.

## Порядок возврата

Любая идея отсюда проходит тот же путь: бриф в `docs/tasks/`, одна сессия,
критерии приёмки. Не смешивать с текущей очередью и не «заодно».
