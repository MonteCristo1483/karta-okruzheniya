## Где мы

- Продукт: PWA «Карта окружения дома», один район — Пресня.
- Сайт: https://montecristo1483.github.io/karta-okruzheniya/
- 3 306 домов, 243 POI, 16 530 маршрутов, 3 306 изохрон, 60 тестов.
- Здания на проде — PMTiles (761 КБ, 176 тайлов) + индекс 341 КБ
  (95 КБ gzip); первый экран зданий ~188 КБ, фолбэк `?tiles=0` на geojson.
  Deploy собирает tippecanoe в Docker (~2 мин), общий прогон 2:46.
- Подложка OSM с улицами и подписями уже есть (PR #36).
- Визуальные цели по решению владельца 21.11: `card-dark-neon.png`,
  `card-diorama-day.png`, `card-diorama-evening.png`. Визуал не принят;
  перенос элементов из макетов разбирается поэлементно. Не считать весь HUD
  разрешённым или запрещённым до фиксации карты элементов; терминология и
  MVP-ограничения SPEC пока действуют. На макетах есть конфликтные подписи
  «Подводные камни», «Оценка локации» и CTA «Отправить клиенту»; без отдельного
  решения остаются термины SPEC §2 и B2C-граница SPEC §4. Карточку пока
  не меняем; V3.1 и прочая доводка карточки отложены по решению владельца.
- Дневная палитра (V1.1, #80): светлая земля, белые улицы, насыщенные парки
  и вода, 5 различимых ступеней балла; выделение — ореол, обводка, акцент
  крыши без заливки тела.
- Окна (V4a, #106): три уровня LOD — flat <15.4, coarse 15.4–17, fine ≥17;
  окна держатся ~10–12 px и не превращаются ни в «одно окно», ни в микросетку.
  Выбор дома ведёт на 16.6, поэтому окна видны сразу после выбора; обзор
  15.35 — чистый. Крыши закрыты roof-cap, custom layer пока не нужен.
  Зоны и маршруты интерполируются по зуму.
- Десктоп: карточка дома — правая панель 420px; мобильная шторка снизу.
- Панель слоёв: чипы на всех экранах, на десктопе 13px (PR #51, #53).
  Поиск и правая карточка дома больше не наезжают на 768–1024: поиск
  прижат влево, карточка `clamp(340px,38vw,420px)`; с xl — центр и 420px.
- Карточка-вердикт с разбивкой, изохроны, МЦД, парки, поиск, `/r/<id>/`.
- Деплой автоматический: push ветки → autopilot (тесты → PR → merge) →
  Deploy (валидатор + golden set → сборка → публикация).
- Данные: официальные реестры там, где есть (метро 96%, парки 39/39,
  школы; стройка 32/56 — решение не выдумывать); промзоны/магистрали без
  реестров.
- Уточнения владельца 21.11: разрешено использовать публичные открытые

  ограничения запросов, дату и покрытие. 39 официальных парков покрыты
  39/39; в POI 40 записей, дополнительный объект требует классификации,

- Для приёмки доступны устройства: OnePlus 15R, Huawei Mate 20, iPhone 11,

## Как работать, чтобы не жечь контекст

- Оркестратор: `docs/ORCHESTRATOR.md` — роли, модели, брифы, ловушки.
- Читать: `HANDOFF.md`, `SPEC.md` §2–4, этот файл. Остальное — только если
  задача их касается.
- Не читать `docs/research/*` целиком и не открывать `.geojson`, `dist/`,
  `node_modules/`.
- Вывод команд — выборками: `Select-Object -Last 20`, `--stat`, grep.
  Не печатать полные логи, диффы и файлы данных.
- Одна задача — одна сессия. Если контекст > ~100k, открыть новую сессию
  с карточкой задачи.
- Исследования и разбор — через subagent (свежий контекст, обратно только
  отчёт).
