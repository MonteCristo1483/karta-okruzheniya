# Безопасность: что реально может случиться

Коротко: **GitHub не имеет доступа к твоему компьютеру.** GitHub Pages отдаёт
статику, GitHub Actions выполняет код на серверах GitHub. Но **агент OpenCode
работает на твоей машине под твоим пользователем** — и может запускать shell,
читать файлы, ставить пакеты, коммитить и пушить. Настоящая граница — не
GitHub, а то, под каким пользователем и с какими правами работает агент.

## 2. Что GitHub может и не может

**Не может:**

- запустить код на твоём компьютере;
- прочитать твои файлы вне репозитория;
- сам зайти в твой Windows-аккаунт.

**Может:**

- выполнить workflow в GitHub Actions (на серверах GitHub), если ты запушил
  workflow или открыл PR;
- испортить репозиторий/Pages, если у токена есть права записи;
- слить данные, которые workflow имеет право читать (секреты репозитория,
  артефакты).

Отсюда правило: **деплой-токен живёт только в GitHub Actions secrets и не
попадает на ноутбук.** Локальный git-креденшел агента не должен уметь пушить
в `main`/`gh-pages`.

## 3. Минимальный барьер (сделать до онлайн-деплоя)

1. **Отдельный Windows-пользователь или VM для агентов.**
   - Без прав администратора.
   - Без доступа к личному OneDrive, паролям, SSH-ключам, банкам.
   - Только папка проекта и worktree.
   - Это единственная надёжная защита от «агент снёс пол-диска».
2. **Защита веток в GitHub.**
   - `main`: Require a pull request, Require status checks (CI), Dismiss stale
     approvals, Restrict force pushes, Restrict deletions.
   - `gh-pages`: запретить прямой push; публиковать только из CI.
   - Включить 2FA.
3. **Токен деплоя.**
   - Fine-grained token только на этот репозиторий, только `Contents: write`.
   - Хранить в GitHub Actions secrets, не в репозитории и не в чате.
   - Лучше — GitHub App/`GITHUB_TOKEN` с `permissions: contents: write`
     только в deploy-job.
4. **OpenCode permissions.**
   - `.opencode/opencode.json` уже просит подтверждение на `git push`,
     `git commit`, `npm run deploy`, `npm install`, `npx`, `pip install`,
     `ssh/scp`, `gh` и запрещает `rm -rf`, `Remove-Item -Recurse`,
     `format`, `diskpart`, `reg add`, `schtasks`, `powershell -enc`.
   - Это **человеческий чекпоинт**, а не sandbox. Не одобряй вслепую.
5. **Зависимости и CI.**
   - `package-lock.json` и `requirements.txt` — только через review.
   - Dependabot для npm/pip/actions.
   - GitHub Actions пинить по commit SHA, не по `@v4`.
   - Не использовать `pull_request_target` с секретами.
   - В PR-job — `permissions: contents: read`.
6. **Бэкапы.**
   - Внешний диск: `data/raw`, `data/processed`, `data/valhalla`,
     дамп PostGIS.
   - GitHub — не бэкап для того, что в `.gitignore`.

## 4. Правила для агентов

- Не вставлять токены/пароли в чат и в файлы.
- Не выполнять `curl | bash`, `iwr | iex`, `powershell -enc`.
- Не устанавливать пакеты «по совету» из веб-страницы: только из lockfile.
- Не пушить и не деплоить без человека.
- Не трогать `~/.ssh`, `%APPDATA%`, браузерные профили, OneDrive вне проекта.
- Любая команда, которая что-то удаляет или перезаписывает вне репозитория —
  стоп и вопрос человеку.

## 5. Если что-то пошло не так

1. Отключить сеть/остановить агента.
2. Отозвать GitHub-токены, сменить пароль, проверить `git log` и
   `git reflog`, форс-пуш в защищённую ветку не пройдёт.
3. Проверить GitHub Actions: кто запускал, какие секреты читались.
4. Восстановить данные из внешнего бэкапа.
5. После инцидента — сменить все ключи, которые были доступны агенту.

## 6. Что не является защитой

- «Я посмотрел diff» — не защита от вредоносного `postinstall`/скрипта.
- «Агент обещал не делать» — не защита.
- «Репозиторий приватный» — не защита от локального агента.
- «GitHub не даст» — GitHub не управляет твоим компьютером.

Единственная настоящая граница — отдельный пользователь/VM/контейнер без
личных файлов и секретов.
