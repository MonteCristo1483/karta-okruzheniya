# Задача E2: сглаживание на 1× мониторах

Дата: 2026-11-20. Причина «на телефоне красиво, на компе пиксельно»:
десктоп рендерит в 1× без сглаживания, телефон — в 2–3×.

## Замеры (браузер владельца, прод)
- `devicePixelRatio = 1`, канвас 1296×886 физических пикселей.
- GPU: RTX 2060 SUPER, ANGLE/D3D11 — ускорение включено, 16 ядер.
- Простой: медиана кадра 16.7 мс, p95 16.9, кадров >33 мс — 0.
- Зум 1.5× и обратно: медиана 16.7, p95 16.8, >33 мс — 5 из 195.
Вывод: нехватки fps нет, страдает качество кромок (алиасинг).

## Задача
1. В `new maplibregl.Map({...})` добавить `antialias` **условно**:
   `antialias: typeof window !== "undefined" && window.devicePixelRatio < 1.5`
   — на телефонах (2–3×) не включаем, чтобы не жечь батарею.
2. Замерить после включения: медиана/p95 кадра при зуме на 1290×900 и на
   1920×1080, сравнить с числами выше. Допустимо ухудшение до ~17.5 мс
   медианы, кадров >33 мс — не больше 10 из 200.
3. Если кромки всё ещё заметно рвутся — попробовать `pixelRatio: 1.5`
   только при `devicePixelRatio === 1`, снова замерить; если fps падает
   ниже порога — откатить и оставить antialias.
4. Скриншоты для отчёта — **в DPR 1 и DPR 2** (в `shot.mjs` есть
   `deviceScaleFactor`; для DPR 1 параметр 1). Приложить пару «до/после».

## Что нельзя
- Менять палитру, слои, данные, карточку.
- Включать antialias безусловно для всех устройств.
- main/gh-pages, force-push, `npm run deploy`.
