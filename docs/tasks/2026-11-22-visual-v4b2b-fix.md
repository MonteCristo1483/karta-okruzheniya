# Задача V4b2b-fix: вернуть читаемую тень при чистом дневном свете

Дата: 2026-11-22. Модель: **GPT-6 Luna**.

Это ограниченная коррекция V4b2b после замера, не третья итерация Argon.
P1 #42 уже исправлен (#144): выбор/окна/reveal в задачу не входят.

## Факты, от которых исходим

В `web/app/map.tsx` сейчас:

```text
MAP_LIGHT.light: color #fff6ea, intensity 0.70,
                 anchor viewport, position [1.5, 245, 46]
```

На одинаковой камере z16.6 / pitch 55 / bearing −25, DPR 1:

- V4b2a `#fff1dc / 0.60`: теневые грани luma 63–67, крыши с жёлтой вуалью.
- `#fff6ea / 0.75`: luma 40–43, отклонено.
- текущий `#fff6ea / 0.70`: luma 48–51, визуал V4b2b не принят хабом.
- Исполнитель подтвердил: повышение intensity в этой сцене уменьшает ambient
  и затемняет отвёрнутые грани. Поэтому больше не исходим из обратного
  предположения.

## Цель

Оставить менее жёлтый `#fff6ea`, но вернуть теневые фасады минимум к читаемости
baseline, без плоского пересвета. Разрешено менять **только одно число**:
`MAP_LIGHT.light.intensity`.

## Обязательный вариант

```text
MAP_LIGHT.light.intensity: 0.70 → 0.50
```

`color` остаётся `#fff6ea`; `anchor`, `position`, `MAP_LIGHT.dark`, roof-токены
и все остальные значения не меняются.

Допустима максимум **одна** поправка после замера тех же пяти домов:

- если медиана теней всё ещё <70 или есть дом <63 — только `0.48`;
- если грани почти сравнялись по яркости/объём пропал — только `0.52`.

Третий вариант и другие значения не подбирать. Если 0.50 и разрешённая
поправка не проходят критерий — остановиться с таблицей luma.
