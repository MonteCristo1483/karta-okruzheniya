# Задача R1: одна страница «Поделиться» вместо страницы на дом

Дата: 2026-11-24. **Модель: DeepSeek V4.1 Flash (`opencode-go/deepseek-v4.1-flash`).**
Полоса: `web/` и `.github/workflows/deploy.yml`. Данные и пайплайн не трогать.

## Контекст

Сейчас `web/scripts/generate-building-pages.mjs` создаёт `dist/r/<id>/index.html`
для каждого дома. На трёх районах это 3 579 файлов (~24 МБ). На Москве —
**100 049 жилых домов**, то есть ~100 тыс. файлов и ~700 МБ; вместе с данными
(265 МБ) сайт упирается в лимит GitHub Pages 1 ГБ.

Нужно: одна страница-шаблон, которая по ссылке открывает нужный дом, и
редирект для старых ссылок `/r/<id>/`.

## Что сделать

1. **`/r/` как страница приложения** (Next.js, `output: export`, basePath
   `/karta-okruzheniya`): клиентский компонент читает `b` (допустим и `id`)
   из query. Если число — `router.replace("/?building=<id>")`. Если нет —
   короткий текст «Ссылка неполная» и ссылка на карту. Никаких запросов
   к данным, никакой карточки на этой странице.
2. **`web/public/404.html`** — редирект для старых ссылок. GitHub Pages
   отдаёт `404.html` на неизвестные пути. Скрипт: если `location.pathname`
   совпадает с `/karta-okruzheniya/r/<цифры>/` → `location.replace` на
   `/karta-okruzheniya/r/?b=<цифры>`; иначе → на главную. Учесть, что
   basePath может отличаться на локальном `npm run dev` (не ломать dev).
3. **Убрать генерацию страниц**: удалить шаг `Generate share pages` из
   `deploy.yml`. `generate-building-pages.mjs` больше не вызывается —
   файл можно оставить до следующей уборки, но нигде не запускать.
4. OG-теги остаются на главной странице приложения (как сейчас). Превью
   на каждый дом осознанно теряем — это уже принятое решение.

## Что нельзя

- Менять карту, карточку, палитру, материалы, скоринг, данные, формат
  данных, `/r/`-содержимое карточки.
- Добавлять зависимости и серверные функции.
- Генерировать файлы на дом в любом виде.

## Проверка

```powershell
cd web
node node_modules\typescript\bin\tsc --noEmit -p tsconfig.json
npm run build
npm run e2e
```

Проверить руками на собранном `dist` (статический сервер с basePath):
- `/r/49553156/` → редирект → карточка дома 49553156;
- `/r/?b=49553156` → редирект → та же карточка;
- `/r/` без параметра → «Ссылка неполная» + ссылка на карту;
- `?building=` на главной работает как раньше.

## Критерий приёмки

1. В `dist` **нет** каталогов `r/<id>/`, только `r/index.html`.
2. Старая ссылка `/r/<id>/` открывает нужный дом (через 404.html).
3. Новая ссылка `/r/?b=<id>` открывает тот же дом.
4. `deploy.yml` не содержит генерации страниц; сборка зелёная.
5. `tsc`, build, 4 e2e; дифф только в `web/` и `deploy.yml`.

## Стоп-условия

- GitHub Pages не отдаёт `404.html` для вложенных путей — стоп и отчёт
  (тогда возвращаемся к варианту с редиректом через `<meta refresh>`).
- Нужны изменения карты/карточки — стоп.
- 60 минут — стоп с отчётом.
