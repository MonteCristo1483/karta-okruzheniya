# Подзадача PERF-2-ZOOM16: убрать просадку FPS от 3D-рейкаста на `mousemove` (`z15–16`)

Дата: 2026-11-25. **Модель: DeepSeek V4.1 Flash (`opencode-go/deepseek-v4.1-flash#high`).**
Полоса: только `web/app/map.tsx` (строки `~4955–4980`).

## Диагноз

На `z15–16` обработчик `map.on("mousemove")` (строка `~4959`) на каждое событие движения мыши (60–120 раз/с) вызывает два `map.queryRenderedFeatures(e.point, ...)`: по всем 3D-слоям зданий `buildingHitLayers()` и по всем слоям POI `poiHitLayers()`. CPU-рейкаст по 3D-экструзии сотен домов в кадре съедает 10–25 мс на событие.

## Что сделать в `web/app/map.tsx`

1. В `map.on("mousemove")` (строки `~4959–4967`):
   - Если `map.isMoving() || selectionMovePending` — немедленно выходить (`return`), не вызывая `queryRenderedFeatures`.
   - Троттлить проверку по времени: не чаще одного раза в `60 мс` (хранить `lastHoverCheckMs` / таймер).
   - Сначала проверять лёгкие 2D-слои `poiLayers`: если `queryRenderedFeatures(e.point, { layers: poiLayers }).length > 0`, сразу ставить `cursor = "pointer"`, **не вызывая** тяжёлый 3D-рейкаст по `buildingHitLayers()`.
   - Менять `map.getCanvas().style.cursor` только если новое значение отличается от предыдущего (`lastCursor`).

## Проверка

- `tsc --noEmit`, `npm run build`, `npm run e2e`.
- Замер `?perf=1` на `z16` при активном движении мыши и вращении/панораме.
