# Задача V2-S2c: три района на проде (новый формат данных)

Дата: 2026-11-23. **Модель: GPT-6 Luna (`opencode-go/gpt-6-luna`).**
Fallback — DeepSeek V4.1 Flash, только по явному решению владельца.
Полоса: `web/`, `.github/workflows/deploy.yml`, `pipeline/validate_export.py`.
Данные — ветка `data`. Визуал, карточку и скоринг не менять.

## Контекст

Шаги 1–2b закрыты: район — параметр, `is_home`, три района, шарды
маршрутов, колоночный индекс (52 КБ на 3 579 домов), PMTiles подложки,
манифест. Сейчас прод живёт на старом формате (Пресня). Цель шага —
переключить прод на новый формат и показать три района.

## Контракт данных (уже собран, менять формат нельзя)

```
data/districts/manifest.json      v, index, districts[]{id,name,bbox,files[]}
data/index.json.gz                {"v":1,"ids":[],"lon":[],"lat":[],"addr":[]}
data/districts/<id>/buildings.geojson | .pmtiles
data/districts/<id>/basemap.geojson   | .pmtiles
data/routes/<id>/<shard>.json.gz       shard = building_id % 16
data/isochrones/<id>/<shard>.json.gz   внутри {"<building_id>": payload}
```

Пути в манифесте — от корня сайта (`data/...`). Архив распаковывается в
`web/public/`, чтобы получилось `web/public/data/...`.

Дополнительно собрать **городские** файлы (один источник на карту, иначе
125 районов дадут 125 источников):

```
data/buildings.pmtiles   — из трёх buildings.geojson (build_tiles.py --geojson)
data/basemap.pmtiles     — из bbox трёх районов (build_basemap.py --pmtiles)
```

Эти два имени фиксированы; манифест их не описывает.

## Что сделать

1. **Карта**: `buildings` и `basemap` читаются из `data/buildings.pmtiles` и
   `data/basemap.pmtiles`, без `?tiles=0`-фолбэка на город (фолбэк оставить
   только на пустой/битый ответ — плашка ошибки).
2. **Поиск**: `data/index.json.gz`, грузится **при первом обращении к поиску**,
   а не на старте; колоночные массивы → тот же результат, что сейчас.
3. **Маршруты и изохроны**: район определяется по `bbox` из манифеста
   (первый подходящий), затем `data/routes/<district>/<id % 16>.json.gz`.
   Один запрос на выбор дома, кэш шардов в памяти.
4. **Нежилое**: клик по зданию с `is_home=false` → плашка
   «Нежилое здание. Индекс окружения считается только для жилых домов»,
   без запроса маршрутов и без карточки. Жилые — как сейчас.
5. **`/r/`**: генератор читает `data/districts/*/buildings.geojson` вместо
   одного файла Пресни. Пока оставляем страницу на дом (3 579 штук, ~24 МБ) —
   шаблон будет отдельным шагом.
6. **Деплой**: архив распаковывается в `web/public`; если в архиве есть
   `data/buildings.pmtiles`, tippecanoe **не запускать**; валидатор получает
   режим нового формата (манифест + выборочная сверка sha256), старый режим
   остаётся для отката.

## Порядок публикации (важно)

1. Собрать `data.zip` нового формата из `data/` (Python `zipfile`).
2. Локально: `npm ci`, `npm run build`, `npm run e2e`, поднять `dist` и
   проверить три района, поиск, маршруты, плашку.
3. Запушить `data.zip` в ветку `data` (старый zip остаётся в истории — это
   откат).
4. Сразу запушить кодовую ветку, чтобы Deploy поднялся на согласованных данных.
5. После Deploy проверить прод: `?building=` в Пресне, Тверском, Арбате.

## Что нельзя

- Менять материалы, палитру, камеру, карточку, `config/scoring.json`,
  `config/buildings.json`, формулу.
- Трогать `?tiles=0`-поведение для Пресни до переключения (после — только
  ошибка).
- Добавлять зависимости (maplibre, pmtiles, fflate уже есть — проверить).
- Менять формат шардов/индекса/манифеста.
- Коммитить `data/`, `*.gz`, `*.pmtiles`, `*.geojson`.

## Критерий приёмки

1. На проде видны три района; здания, крыши и ступени — как раньше.
2. Поиск находит адрес в любом из трёх районов; индекс грузится не на старте
   (проверить сетевой лог: до первого поиска запроса нет).
3. Выбор жилого дома в Тверском и Арбате: карточка, маршруты, изохроны.
4. Клик по гаражу/ТЦ/офи­су: плашка, **ноль** запросов к `routes/`/`isochrones/`.
5. `/r/<id>` открывается для дома из нового района.
6. Deploy ≤ 8 минут, архив ≤ 40 МБ, ошибок консоли нет.
7. `tsc`, build, 4 e2e зелёные; дифф не выходит за полосу задачи.

## Стоп-условия

- Архив > 60 МБ или Deploy > 12 минут — стоп, отчёт.
- Без нового `buildings.pmtiles` карта не рисуется, а фолбэк тянет 18 МБ
  geojson — стоп, не публиковать.
- Нужны изменения скоринга, карточки или материалов — стоп.
- 150 минут — стоп с отчётом, ветку `data` не трогать до успешной локальной
  проверки.

## Отчёт (≤40 строк)

1. PR, commit, diffstat.
2. Локальные проверки: три района, поиск, маршруты, плашка, `/r/`.
3. Прод после Deploy: три `?building=` ссылки, время деплоя, размер архива.
4. Сетевой лог: какие файлы грузятся на старте, какие при поиске и выборе.
5. Риски одной строкой. Полный прогон и `/r/`-шаблон — не в этом шаге.
