# Задача LOD-A: пирамида тайлов и лимит размера

Дата: 2026-11-24. **Модель: DeepSeek V4.1 Flash (`opencode-go/deepseek-v4.1-flash`).**
Полоса: `pipeline/build_tiles.py`, `pipeline/build_basemap.py`,
`web/scripts/tile-size.mjs` (инструмент замера). `web/app/` не трогать.

## Контекст

Прод тормозит. Замеры: buildings.pmtiles z12 — **3,1 МБ** на тайл, z13 — 1,5 МБ;
подложка z8 — 975 КБ, z9 — 1,16 МБ. На экране 20–30 тайлов, итого 30–90 МБ.
Причина: тippecanoe собран с `-Z12` без прореживания, на малых зумах в тайл
попадает вся застройка. Маршруты, изохроны, индекс и скоринг не виноваты.

## Что сделать

1. **Инструмент замера** — `web/scripts/tile-size.mjs`: принимает путь к
   PMTiles и печатает размеры тайлов на z8…z16 для точки Москвы (37.62, 55.75),
   плюс minZoom/maxZoom/numAddressedTiles. Закоммитить как dev-инструмент.
2. **Здания**: пересобрать `data/buildings.pmtiles` с низкоуровневой
   пирамидой и ограничением размера. Стартовые флаги:
   `-Z9 -z16 -d13 --drop-densest-as-needed --maximum-tile-bytes 500000`.
   Если z16 теряет форму домов — вернуть `-d13` (он уже там) и уменьшать
   только лимит тайла; `-d12` пробовать только при явной необходимости.
3. **Подложка**: `-Z6 -z16` + `--drop-densest-as-needed --maximum-tile-bytes 300000`
   (сейчас z8 = 975 КБ).
4. Пересобрать только тайлы. Маршруты, изохроны, геометрию зданий и
   артефакты районов не пересчитывать.
5. Собрать новый `data.zip` (та же структура `data/...`), **не загружать**:
   загрузку и деплой делает оркестратор.

## Ориентиры (критерий)

| Зум | Сейчас | Цель |
|---|---|---|
| z9–11 | нет тайлов | ≤ 300 КБ |
| z12 | 3,1 МБ | ≤ 600 КБ |
| z13 | 1,5 МБ | ≤ 600 КБ |
| z14 | 346 КБ | ≤ 400 КБ |
| z15–16 | 40 / 3 КБ | без ухудшения |

Плюс: `buildings.pmtiles` ≤ 120 МБ (сейчас 86), `basemap.pmtiles` ≤ 60 МБ.
