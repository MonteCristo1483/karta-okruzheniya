# Задача Tiles-B: бюджет тайлов z13–15

Дата: 2026-11-24. **Модель: DeepSeek V4.1 Flash.**
Полоса: `pipeline/build_tiles.py`, `pipeline/build_basemap.py`.
`web/app/` не трогать, релиз не грузить, деплой не запускать.

## Контекст

Обзор облегчили, но рабочий зум 14–15 тяжёлый: z14 — 346 КБ на тайл,
z13 — 275 КБ, в кадре 15–25 тайлов. Пользователь видит загрузку «кусками».
Цель — бюджет: один тайл ≤200 КБ на z13–14, ≤80 КБ на z15, при сохранении
вида на z16.6.

## Что сделать

1. Пересобрать `data/buildings.pmtiles`:
   - `--maximum-tile-bytes 220000`, `--drop-densest-as-needed`;
   - попробовать `-d12` вместо `-d13` и сравнить z16.6: если форма крыш и
     контуры домов не деградировали — оставить `-d12`; если деградировали —
     вернуть `-d13` и снижать только лимит;
   - мелкие постройки (площадь/класс) на z13–15 можно прореживать сильнее:
     если tippecanoe-фильтр по атрибутам доступен — использовать, иначе
     только drop.
2. Пересобрать `data/basemap.pmtiles`: z8 ≤400 КБ (сейчас 533), z9 ≤400
   (сейчас 534), z10–11 без ухудшения.
3. Замеры тем же `node web/scripts/tile-size.mjs` на z9–16 для обоих файлов.
4. Один кадр z16.6 light DPR1 `?building=64091236` — сравнить с текущим.
5. Собрать `data.zip` (структура `data/...`), **не загружать**: загрузку и
   деплой делает оркестратор. Старый сохранить как `data.zip.pre-tiles-b`.

## Критерии

| Зум | Сейчас | Цель |
|---|---|---|
| z13 | 275 КБ | ≤200 КБ |
| z14 | 346 КБ | ≤220 КБ |
| z15 | 40 КБ | без ухудшения |
| z16 | 3 КБ | без ухудшения |

Плюс: z16.6 визуально без деградации (крыши, контуры, окна).

## Что нельзя

- Менять `web/app`, стиль, скоринг, данные районов, маршруты/изохроны.
- Загружать релиз, деплоить, пушить в `data`.
- Добавлять зависимости.

## Стоп-условия

- z16.6 визуально хуже (форма/крыши) — вернуть `-d13`, стоп с отчётом.
- Не удаётся уложить z14 в 250 КБ без потери вида — зафиксировать факт,
  это вход в решение про растровый обзор.
- 90 минут.
