# Задача P1: перцентили в индексе (чтобы тайловый режим не терял строку «хуже N%»)

Дата: 2026-11-20. Маленькая задача в `karta-pipeline`. Клиент не трогаем.

## Зачем
В тайловом режиме карточка теряет строку «хуже N% домов Пресни»: клиент считал
перцентили по `breakdown.penalties[kind].distance_m` всех домов, а `breakdown`
теперь живёт только в `routes/<id>.json` (по одному дому) — распределение не
собрать. Решение: посчитать перцентили на экспорте и положить в индекс.

## Прочитать
1. `docs/research/pmtiles-plan.md` — «Факт замера»
2. `docs/STATE.md`
3. `pipeline/build_tiles.py` — только `build_index()` и константы `INDEX`,
   `FIELDS` (~30–150)
4. `web/app/map.tsx` — только `penaltyDistances` / `percentileFor`, чтобы
   повторить ту же формулу (порядок сортировки и округление)

Не читай `*.geojson` целиком, `web/app/*` кроме указанного, `dist/`.

## Задача
1. В `build_index()` добавить в каждую строку четыре перцентиля —
   `road`, `railway`, `construction`, `industrial`, — посчитанные ровно как
   в клиенте (`percentileFor`): доля домов района, у которых расстояние
   больше/меньше (как в текущем коде), округление до 3 знаков.
   Значение `null`, если у дома нет `distance_m` для этого вида.
   Строка остаётся массивом: сначала прежние 6 полей, затем 4 перцентиля —
   старый клиент от лишних полей не ломается.
2. Формат `FIELDS`/комментарии в шапке обновить.
3. Проверить на текущей выгрузке:
   - размер индекса до/после (ожидаем +80–120 КБ raw, +20–30 КБ gzip);
   - у дома `64091236` перцентиль дороги совпадает с тем, что показывает
     прод сейчас (≈0.96);
   - повторный прогон побайтово идентичен.
