# Задача LOD-B: плоский обзор, туман, плавный рост домов

Дата: 2026-11-24. **Модель: Gemini 4 Argon, effort High.**
Fallback — GPT-6 Luna, только по явному решению владельца.
Полоса: `web/app/map.tsx`, `web/app/theme.ts` (цвета тумана). Данные, пайплайн,
карточку, скоринг и логику POI не трогать.

## Контекст

Тайлы уже прорежены (LOD-A): z12 — 944 КБ вместо 3,1 МБ, z9–11 — новые.
POI переведены на symbol-слой. Но обзор всё ещё рывками: на малых зумах
рисуются 3D-экструзия всех зданий, три слоя теней, деревья и подписи.

Решение продуктовое: **обзор — это карта, 3D — при приближении**. Плюс
туман по дальности (как в играх) и ограничение наклона, чтобы город не
грузился «до горизонта». Плюс плавный рост домов вместо щелчка 2D→3D.

Мобильный режим упрощения (отключение теней, antialias, понижение DPR на
телефоне) **в этот шаг не входит** — отдельно. Но сами нововведения (плоский
обзор, туман, рост домов, maxPitch) применяются **на всех устройствах
одинаково**: версии синхронные, никакого device-gating для них.

## Что сделать

1. **Плоский обзор.** Ниже z14 не рисовать: здания (все слои `buildings*`,
   включая тени), деревья, подписи улиц. Остаются подложка, вода, парки,
   POI по действующему правилу (метро с z11).
   Реализация — `minzoom: 14` на соответствующих слоях, без переписывания
   логики.
2. **Плавный рост домов.** Здания появляются на z14 и «вырастают» до
   z14.6: `fill-extrusion-height` интерполируется от 0 до реальной высоты
   на этом отрезке. Выбранный дом и hero-окна (z16.6) не затрагиваются.
3. **Туман.** Нативный `fog` в стиле MapLibre: цвет под тему (день —
   светлый тёплый, тёмная — холодный), `horizon-blend` мягкий. Проверить,
   что он не заливает центр и не мешает подписям.
4. **Ограничение наклона.** `maxPitch` 55–60° вместо почти горизонтального
   взгляда; проверить, что выбор дома (доворот камеры) не сломан.
5. **Ничего не менять** в POI-правилах, карточке, палитре пяти ступеней,
   выбранном доме, скоринге.

## Что нельзя

- Менять данные, тайлы, пайплайн, формат, `/r/`, деплой.
- Трогать мобильные настройки, DPR, antialias.
- Добавлять зависимости.
- Менять внешний вид на z15–16.6 (паритет).

## Проверка

```powershell
cd web
node node_modules\typescript\bin\tsc --noEmit -p tsconfig.json
npm run build
npm run e2e
```

Кадры — **4 штуки, DPR 1, light** (экономия, без пакета):
1. z11 — обзор: только карта, без домов, теней и деревьев;
2. z14.2 — дома в процессе роста (высота промежуточная);
3. z16.6 `?building=64091236` — паритет с текущим;
4. z16.6 dark — туман не ломает тёмную тему.

Плюс замер: сколько байт грузится на первом экране z11 (сетевой лог,
только подложка и POI). Если > 3 МБ — записать в отчёт (это вход в решение
про растровый обзор).

## Критерий приёмки

- На z10–13 карта двигается плавно, в кадре нет 3D, теней и деревьев.
- Дома появляются без щелчка: рост на z14–14.6.
- На z15–16.6 визуальный паритет: крыши, окна, выбранный дом, пять ступеней.
- Туман виден при наклоне, но не «молоко»; тёмная тема не серая.
- `maxPitch` ограничен, автодоворот при выборе дома работает.
- `tsc`, build, e2e зелёные; дифф только в `web/`.

## Стоп-условия

- Туман заливает центр или мешает читаемости — одна поправка цвета/blend,
  вторая — стоп и отчёт.
- Рост домов выглядит как щелчок или ломает выбранный дом — стоп.
- Нужны правки данных/пайплайна — стоп.
- 90 минут — стоп с отчётом.
