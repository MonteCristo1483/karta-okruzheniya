# Задача V2-S3b: Москва целиком — подготовка прогона

Дата: 2026-11-23. **Модель: DeepSeek V4.1 Flash (`opencode-go/deepseek-v4.1-flash`).**
Полоса: `pipeline/`, `config/buildings_overrides.json`.
**`web/`, скоринг, формулу, ветку `data` не трогать. Расчёт маршрутов не запускать.**

## Контекст

Три района на проде. Дальше — вся Москва. Прогон это часы локального CPU
(~149–212 тыс. жилых, 745 тыс.–1 млн маршрутов), поэтому сначала нужно:
правильно определить границы, узнать реальный объём, подготовить один
оркестратор с резюмируемостью. Сам batch запускает владелец отдельно.

Известно: в `districts` 1 540 записей, включая Подмосковье. Адресное
покрытие 76,3%, год постройки 23,1% — это не чинится здесь, но и не
выдумывается: где нет данных, карточка показывает «нет данных».

## 1. Границы Москвы

- Извлечь из `data/raw/moscow.osm.pbf` границу города (`boundary=administrative`,
  `admin_level=4`, «Москва») в таблицу `moscow` — по образцу
  `extract_presnensky.py`, без хардкода relation id: искать по тегам и имени.
- Районы города = `districts`, чей центроид попадает внутрь `moscow`
  (`ST_Contains`). Записать функцию/вьюху `moscow_districts`.
- **Отчёт**: сколько районов получилось (ожидаем ~125 + поселения Новой
  Москвы; если получилось 100 или 400 — стоп, разбираемся). Список имён.

## 2. Реальный объём

Один запрос: сколько `is_home` зданий внутри каждой `moscow_districts`,
и сумма. Вывести таблицу: район, зданий, жилых, доля жилых.

- Если жилых **больше 300 тыс.** — стоп и отчёт: оценка времени и размера
  выходит за бюджет, решает владелец.
- Оценка прогона: маршрутов = жилых × 5, изохрон = жилых. Указать часы при
  8 воркерах (по факту 2b: 2 545 маршрутов за 55 с).

## 3. Исключения для «офисных» жилых комплексов

`config/buildings_overrides.json`:

```json
{"v":1,"overrides":[{"osm_id":123,"is_home":true,"reason":"апартаменты, <источник>"}]}
```

- Механизм: `buildings_filter.py` применяет overrides последними, после
  тегов. Override с `is_home:false` тоже допустим.
- Стартовый список — башни Москва-Сити, размеченные в OSM как
  `building=office|commercial`, но фактически жилые (Neva Towers и др.).
  Найти их запросом в bbox Сити по имени, добавить 5–10 записей **с
  источником в `reason`** (например, «апартаменты, сайт ЖК»). Не угадывать:
  если факт не подтверждён, запись не добавлять.
- Проверка: после реклассификации эти здания `is_home=true`; в Пресне
  число жилых выросло ровно на число добавленных.

## 4. Оркестратор `pipeline/run_city.py`

Один вход, этапы, резюмируемость:

```
run_city.py --stage boundaries|export|routes|iso|pack|tiles|all --districts all|id,id --dry-run
```

- `export`: здания/POI/красные зоны по району → `data/districts/<id>/`
  (переиспользовать `export_map_data.py`/`build_district.py`).
- `routes` / `iso`: только `is_home`, резюмируемо (готовое не пересчитывать),
  с журналом отказов по id.
- `pack`: шарды + индекс + манифест.
- `tiles`: **один городской** `buildings.pmtiles` и `basemap.pmtiles`
  (не 125 файлов), per-district PMTiles больше не нужны.
- `--dry-run`: печатает план (сколько районов, домов, файлов, оценка времени)
  и ничего не пишет.

Требование: повторный запуск после падения продолжает с места остановки.

## Что нельзя

- Запускать полный `all` без `--dry-run` в этой сессии.
- Менять `web/`, скоринг, формат шардов/индекса/манифеста, `/r/`.
- Менять `is_home`-правило кроме overrides.
- Скачивать новый PBF (регионального хватает), добавлять зависимости.
- Пушить в ветку `data`, создавать релизы, деплоить.

```powershell
pipeline/.venv/Scripts/python.exe pipeline/run_city.py --stage all --dry-run
pipeline/.venv/Scripts/python.exe pipeline/run_city.py --stage export --districts 1275551,1257786,1257484
pipeline/.venv/Scripts/python.exe -m unittest discover -s pipeline -p "test_*.py" -v
```

Экспорт трёх районов должен дать те же артефакты, что сейчас (числа и
размеры в пределах ±2%); расхождение — разбор, а не «пересоберём».

## Критерий приёмки

1. Список районов Москвы с числами (район/зданий/жилых).
2. `--dry-run` печатает план на весь город: районы, жилые, маршруты,
   изохроны, оценка часов и размера.
3. Overrides работают; Сити-башни стали жилыми; других изменений нет.
4. Экспорт трёх районов воспроизводим.
5. 64+ тестов зелёные; `web/` и `config/scoring.json` без диффа.
6. В отчёте — что именно запускать владельцу и сколько это займёт.

## Стоп-условия

- Районов Москвы не ~125, а заметно больше/меньше — стоп, отчёт.
- Жилых > 300 тыс. — стоп, решает владелец.
- Overrides требуют правок в `web/` или скоринге — стоп.
- 120 минут — стоп с отчётом, batch не запускать.

## Отчёт (≤40 строк)

1. PR, commit, diffstat.
2. Районы и жилые: сумма и 5 самых больших/маленьких.
3. `--dry-run`: маршруты, изохроны, часы, размер.
4. Overrides: сколько записей, какие, источник.
5. Точная команда для владельца и ожидаемое время.
6. Риски одной строкой.
