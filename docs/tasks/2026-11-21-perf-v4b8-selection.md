# Задача V4b8: плавность выбора дома + мягкий доворот камеры

Дата: 2026-11-21. Блокер от владельца: «при быстром переключении между
домами карта виснет, всё не очень быстро, анимации дёрганые — просели по
плавности сильно». Началось после hero-окон (V4b4, #115) и фикса контура
(V4b5, #120). Сначала плавность, потом красота.

## Что подозреваем (проверить профилем, не на глаз)

На каждый клик синхронно, в главном потоке:
1. `captureSelectedBody` — `querySourceFeatures` по всем загруженным тайлам;
2. union через `polygon-clipping`;
3. генерация до ~2 000 оконных extrusion-квадов;
4. `addSource` / `addLayer` / `removeLayer` + пересборка свечения;
5. повтор на `sourcedata` / `idle` и при смене темы.
При быстрых кликах предыдущая работа не отменяется — несколько сборок
наслаиваются, карта замирает.

## Задача

### 1. Один проход на выбор, с отменой
- На клик — только дешёвое: подсветка/свечение по уже известному контуру и
  старт `flyTo`. Тяжёлая сборка окон — после `moveend`/`idle`.
- Токен выбора (sequence id): при новом клике старая сборка отменяется,
  её результат не применяется.
- Не больше **двух** сборок окон на одно переключение (включая догрузку
  тайлов); в консоль — счётчик `build #n` для проверки.

### 2. Быстрые пути
- Один полигон в контуре → **без** `polygon-clipping` (сейчас union
  вызывается всегда).
- Кэш по `id`: повторный выбор того же дома не пересобирает окна.
- `sourcedata` пересобирает только если контур реально изменился
  (сравнение площади/хэша), а не на каждую загрузку тайла.
- Смена темы — только `setPaintProperty`, без rebuild геометрии.

### 3. Бюджет геометрии
- Окна: не больше **1 200** полигонов; ореол — только на десктопе
  (ширина ≥768 px), на телефоне без ореола.
- Свечение (3 обводки) оставить: оно дешёвое; но пересчитывать только при
  смене дома, не на каждый кадр.

### 4. Мягкий доворот камеры (решение владельца)
- Считать угол между нормалью самого длинного фасада и текущим лучом
  зрения.
- Доворачивать **только** если фасад почти с ребра (|угол| < 20°),
  и не больше **±35°** от текущего bearing; иначе bearing не менять.
- Анимация 600–800 мс, без рывка; повторный клик не запускает второй
  доворот поверх первого.

- Не убирать hero-окна и свечение — только сделать их дешёвыми.
- Не добавлять новые зависимости.

## Как мерить (обязательно числами)

В Chrome с GPU (не headless WebKit), 1290×900, DPR 1:
1. Базлайн — текущий `main` до правок: 5 быстрых переключений между
   домами за 3 секунды (клик по дому → сразу следующий).
2. После правок — тот же сценарий.
3. Записать: long tasks >50 мс, худший кадр, fps в полёте, число сборок
   окон на переключение, время от клика до начала движения камеры.
4. Порог приёмки: long tasks >50 мс — не больше 2; UI не замирает
   дольше 200 мс; fps в полёте ≥45; сборок ≤2 на переключение; клик
   отзывается <120 мс.

Плюс `tsc`, `npm run build`, `npm run e2e` — зелёные.
Скриншоты не нужны, нужен перф-отчёт «до/после».

## Критерий приёмки

Быстрое переключение между 5 домами не вешает карту: анимация плавная,
клики отзываются сразу, окна и свечение появляются после прилёта. Камера
доворачивается мягко и только когда фасад почти с ребра (≤±35°). Данные
и визуал не изменились. Таймбокс — 70 минут; если просадка не
воспроизводится в замере — отчёт с профилем и точным местом.
