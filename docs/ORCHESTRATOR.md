## Цикл одной задачи

1. Оркестратор выбирает **одну** задачу и пишет бриф по шаблону ниже.
2. Пользователь открывает **новую сессию-исполнитель**, выбирает модель,
   вставляет бриф.
3. Исполнитель: ветка от `origin/main` → правки → `tsc`/`build` → push.
4. Autopilot: тесты → PR → merge → Deploy. Если упал — merge `origin/main`,
   разрешить конфликт, push. Не обходить тесты и не мержить руками.
5. Исполнитель присылает отчёт и 4 скриншота WebKit.
6. Оркестратор проверяет PR/Deploy/скриншоты: принять или дать короткую правку.
7. Значимое решение — строка в `docs/decisions.md`; состояние — `docs/STATE.md`.

## Визуальная проверка

Локальный Chrome 157 и встроенный браузер иногда вешают MapLibre worker
(стиль не грузится, canvas пустой). Это среда, не сайт. Для скриншотов
используем **WebKit через Playwright**:

```powershell
cd C:\Users\starg\AppData\Local\Temp\opencode\pw
node shot.mjs "<URL>" "<out.png>" light 1290 900
node shot.mjs "<URL>" "<out.png>" dark 390 844
```

Скрипт лежит в temp; если его нет — попросить хаб/пользователя, не ставить
новые инструменты вслепую. Скриншоты — в `C:\Users\starg\karta-review\`
или temp; в репозиторий бинарники не коммитить.
