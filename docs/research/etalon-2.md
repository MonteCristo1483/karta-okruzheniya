# Эталон-2: как проверять индекс без подгонки

Дата: 19.11.2026. Источник: исследовательский subagent + проверка ссылок.
Статус: план, код не менялся.

## Диагноз

Список 30 районов (`data/reference_set.md`) не различает модели: константа
6.0 даёт 26/30, текущая формула — 21/30 (HANDOFF §7.1). Значит метрика
«медиана попала в диапазон» измеряет ширину диапазонов, а не качество.
«Глубокий разбор районов» агентами даст второй субъективный лейбл, а не
эталон.

Валидировать надо **факты** (увидела ли модель реальный объект) и
**поведение формулы** (границы, монотонность, кламп), а не итоговую цифру.

## Что проверяем и по каким источникам

| Фактор | Независимый источник | Доступ / лицензия |
|---|---|---|
| Входы метро | data.mos.ru, набор 62329 | API с ключом; единой открытой лицензии не подтверждено |
| Входы МЦД | data.mos.ru, набор про входы МЦД | то же |
| Стройка | data.mos.ru 2941 (активные), 64028 (ввод) | бесплатно, наборы периодически недоступны |
| Промзона | Госреестр НВОС (Росприроднадзор) | публично; условия переиспользования не заданы |
| Школы/сады | Рособрнадзор, открытые данные | можно с атрибуцией |
| Шум | data.mos.ru, передвижная эколаборатория | точечное покрытие, набор может быть пустым |
| Воздух | mosecom.mos.ru | нет публичного API → в продукт не тащить |

Чего нет: открытой шумовой карты с геометрией и официальной
классификации улиц по «магистральности». Часть фактов придётся
фиксировать вручную (фото/скриншот), но это факт, а не оценка.

## План

1. **Сверка слоёв с реестрами** (3–5 дней). Метро, МЦД, школы, стройка,
   промзона: precision/recall при допуске 30 м, пропуски — с id.
   Ловит главную болезнь «POI нет / POI не тот», а не «формула плохая».
2. **Golden set фактов** `data/golden/facts.yaml` (4–6 дней). 40–60 домов,
   стратификация по фактам, а не по оценке: внутри радиуса, снаружи с
   запасом, на границе ±допуск; обязательны негативные кейсы (рядом нет
   стройки/промзоны по двум источникам). Проверка `pipeline/check_golden.py`
   по geojson, без PostGIS. Гейт: `threshold_errors = 0`, pass rate ≥ 0.9.
3. **Инварианты** (1–2 дня). Монотонность, штраф ровно 0 на радиусе,
   сдвиг всех объектов, удаление слоя, кламп, идемпотентность.
4. **Pareto-бенчмарк районов** (5–7 дней). Район A не хуже B по каждому
   официальному факту → индекс A не ниже B больше чем на ε (0.3).
5. **Пилот «шум как внешний критерий»** (3–5 дней + юрпроверка). Только
   после 1–3; если данных мало — закрыть с записью в decisions.

Шаги 1–3 дают ~80% пользы и почти не зависят от юридических рисков.

## Технические ловушки (уже известны)

- Штрафы считаются от **контура** здания, бонусы по маршрутам — от
  **центроида**. Для большого дома это разные точки отсчёта.
- Для зон `ST_Distance = 0` при пересечении → сразу максимальный штраф.
  Это нужен тест, а не «на глаз».

## Чего не делать

1. Не таргетировать 21/30 (константа даёт 26/30 — метрика недействительна).
2. Не строить golden set из оценок (LLM, «эксперт сказал») — только факты
   с id и датой.
3. Не использовать цены как целевую переменную (циркулярно + ToS).
4. Не смешивать правку `config/scoring.json` и golden set в одном PR.
5. Не менять допуски после первого прогона.
6. Не делать исключений по `building_id` в коде.
7. Не тащить источники без лицензии (ГИС ЖКХ, платные API, 2ГИС/Яндекс).
8. Не добавлять шум/PM2.5 в индекс до валидированных измерений.
