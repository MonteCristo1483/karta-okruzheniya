## Доступ, условия и ограничения

- Исследователь сообщает, что [условия data.mos.ru](https://data.mos.ru/terms)
  заявляют CC BY 4.0 с атрибуцией; API требует индивидуальный ключ.
  Частота обновления зависит от набора. Числовой публичный лимит запросов
  исследователь не обнаружил. В текущей проверке web-fetch портала вернул
  только заголовок SPA, поэтому условия конкретного набора надо сохранять
  вместе с его паспортом и версией.
- Для OSM действует ODbL и атрибуция; для производной базы могут действовать
  условия share-alike.
- Владелец разрешил использовать публичные открытые API. Это разрешение
  проекта не заменяет условия конкретного поставщика данных. Не записывать
  «лицензия подтверждена», если подтверждена только доступность API.
- ГИС ЖКХ, ГИС ОГД, НВОС, Мосэкомониторинг и Росреестр/НСПД остаются
  кандидатами либо источниками с неразрешёнными условиями повторного
  использования; это фиксация статуса, не юридическое заключение.

## Предлагаемая агентная сетка

1. **Каталогизатор источников:** паспорт/ID набора, схема, версия, условия,
   атрибуция, лимиты и требования к ключу.
2. **Коннекторы по доменам:** data.mos.ru, OSM, адреса/здания, стройки,
   транспорт. Секреты только из окружения; не передавать моделям и не писать
   в логи.
3. **Нормализатор:** provenance-поля `source_id`, `source_version`,
   `retrieved_at`, геометрия/точность, confidence, coverage; сохранять
   исходные ID и геометрию.
4. **QA-агент:** схема, геометрия, дубли, покрытие по границе Пресни, резкие
   изменения количества и онлайн-сверки независимых источников.
5. **Оркестратор релиза:** отчёт по изменениям; стоп при ошибках валидатора,
   неизвестном источнике или неожиданном падении покрытия. Агент не публикует
   данные и не меняет scoring самостоятельно.

Следующие кандидаты для отдельного исследования — набор 2855 (ордера) и
60661 (остановки). Подключать по одному после проверки схемы, свежести,
условий источника и качества геометрии; сначала описать реестр источников и
provenance, затем менять пайплайн.
