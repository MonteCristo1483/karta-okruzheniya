# Схема онлайн-сетки агентов данных

Подготовлено хабом 21.11.2026 по инвентаризации
`docs/research/data-source-inventory-2026-11-21.md` и уточнениям владельца.
Цель — максимум открытых онлайн-данных для Пресни без полевой проверки,
но без автоматической публикации непроверенных фактов.

## Разделение работы

**Модель не должна быть ETL-движком.** Массовая загрузка, пагинация,
геометрические преобразования и подсчёты — детерминированный Python-код.
LLM используется для поиска/разбора новых источников, объяснения schema
drift и триажа аномалий; итоговые проверки выполняются кодом.

| Роль | Ответственность | Вход → выход |
|---|---|---|
| Источниковед (read-only) | Находит публичные API, изучает паспорта/схемы, лицензии, атрибуцию, лимиты и покрытие | URL/задача → карточка источника со ссылками и неизвестными |
| Разработчик-коннектора | Подключает один набор/источник за задачу: пагинация, версии, retries, rate limit, нормализация | Утверждённая карточка → воспроизводимый адаптер и тесты |
| QA-рецензент (read-only) | Проверяет схему, геометрию, дубли, coverage, изменение количества и независимые сверки | Дифф выгрузки → отчёт pass/fail и причины |
| Хаб/релизный координатор | Выбирает следующую задачу, проверяет отчёт, решает, готов ли снимок к текущему data-release flow | Проверенный кандидат → разрешение на отдельный релиз данных |

Не создавать агента на каждый слой POI. Для параллельной работы — максимум
один коннектор и один read-only рецензент, в пределах правила проекта.

## Поток данных

1. **Registry:** стабильный source ID, владелец, URL, класс доступа,
   набор/версия, условия использования, атрибуция, лимиты, секреты и cadence
   обновления. Неизвестное явно остаётся `unknown`.
2. **Fetch:** API-коннектор или закреплённый OSM-экстракт. Запросы
   идемпотентны, ограничены rate limit, имеют checkpoint и логируют только
   безопасные метаданные. API-ключ берётся из окружения; его не видит LLM.
3. **Staging:** сохраняются source ID и исходные свойства/геометрия; ни
   scoring, ни опубликованный снимок на этом шаге не меняются.
4. **Normalize:** единая provenance-запись: `source_id`, `source_version`,
   `retrieved_at`, исходный ID, координатная система, качество геометрии,
   `coverage`, `confidence`, атрибуция. Не терять происхождение при
   объединении одинаковых объектов.
5. **QA:** схема и допустимые значения; геометрия; дубли; доля объектов,
   попавших в район; резкие изменения количества; пересечение с известными
   независимыми реестрами. Все пороги фиксированы тестами/конфигом, не
   подбираются LLM автоматически.
6. **Diff report:** новые/изменённые/исчезнувшие объекты, coverage по району,
   причины исключений и список неопределённых совпадений.
7. **Release:** только проверенный экспорт идёт в существующий data-release
   flow с валидатором и golden set. Агент не пишет напрямую в `data`, `main`
   или `gh-pages`; scoring не меняется автоматически.

## Стоп-сигналы

- Не установлены правила повторного использования данных или необходимая
  атрибуция.
- API требует неутверждённый доступ, превышается лимит или неясно, можно ли
  выполнять массовую загрузку.
- Изменились схема/координатная система; геометрия повреждена; coverage
  резко изменился; появилось много неоднозначных дублей.
- Новый объект нельзя надёжно отнести к типу факта или к конкретному дому.
- Источник противоречит независимому источнику: сохранить оба значения и
  отчёт о расхождении, а не выбирать «правду» моделью.

Отсутствие данных не восполнять буферами, генерацией координат или
текстовым выводом модели. Если независимой онлайн-сверки нет — показывать
coverage/confidence и помечать факт как неполный.

## Очередь внедрения

1. Утвердить минимальный source registry/provenance-контракт на уже
   используемых источниках — без изменения scoring и опубликованных данных.
2. Разобрать индивидуальный источник года постройки из ГИС ЖКХ: зафиксировать
   применимые условия повторного использования или определить замену.
3. Исследовать 2855 (ордера) отдельно от полигонов стройки; затем 60661
   (остановки) — с проверкой геометрии и свежести.
4. Для каждого нового источника — отдельная реализация и ревью, затем только
   после валидатора решать, включать ли данные в снимок.
5. Позже расширять каталог по школам/садам/магазинам и промышленным факторам.
   Где официального машиночитаемого источника нет, фиксировать пробел, не
   маскировать его «полнотой» OSM.

## Ограничение автоматизации

Сетка может обнаруживать новые источники и проверять данные онлайн, но не
может гарантировать физическую актуальность объекта, законность каждого
неописанного endpoint или причинное значение расстояния для здоровья.
Такие неопределённости отражаются в provenance/confidence; не превращать их
в категоричный вывод в карточке.
