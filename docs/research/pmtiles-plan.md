# PMTiles: план и развилка

Дата: 2026-11-20. Разведка read-only (subagent), без правок кода.
Этап 2 роадмапа. Ниже — факты, честная оценка выигрыша и порядок работ.

## Что проверили

| Вопрос | Ответ |
|---|---|
| Range-запросы на GitHub Pages | **Работают сейчас**: живой прод отдал `206` + `Content-Range` на geojson и og.jpg, в т.ч. из кэша Fastly. В документации GitHub не гарантированы → нужен smoke-тест в CI и фолбэк |
| Клиент | `pmtiles@4.5.0` + `maplibregl.addProtocol("pmtiles", new Protocol().tile)`, source `type: "vector"`. MapLibre 6.17.0 совместим, `setWorkerUrl` не нужен |
| Сборка тайлов | tippecanoe **только из исходников** (в apt нет, бинарников в релизах нет): пин `2.79.0` + сборка 1–2 мин + кэш. Python-пайплайн не меняется, новый `pipeline/build_tiles.py` |
| Где артефакт | тайлы — производные, в git не кладём; собирать в Deploy после валидатора; имя `buildings-<sha8>.pmtiles`; ветка `data` остаётся одним `data.zip` |
| Вес | 4,07 МБ geojson (611 КБ gzip) → ≈0,7–1,2 МБ pmtiles, 220–300 тайлов |
| Первая загрузка | 611 КБ gzip одним куском → ≈120–260 КБ (z15, 6–12 тайлов) + заголовок и индекс |
| Main-thread | сейчас `JSON.parse` 4 МБ + циклы по 3306; с тайлами парсинг кропотливый |

## Честная оценка выигрыша

- **2–3× по байтам**, не 10×: GitHub Pages уже отдаёт geojson в gzip.
- +150–400 мс на iPhone 11 за счёт меньшего парсинга и раннего рендера.
- Главный смысл — не Пресня, а масштаб: 30 районов не влезут в «файл на район».
- POI (38,6 КБ) **тайлить не нужно**: они рисуются DOM-маркерами и требуют
  полного списка. Это поправка к формулировке этапа 2 роадмапа.

## Скрытая стоимость: клиент завязан на полную коллекцию

`map.tsx` берёт из загруженного geojson: поисковый индекс, центры домов,
квинтили цвета, перцентили штрафов, ближайшие POI, `allIds` для
feature-state, `breakdown` для карточки. Без этого получим «карта есть,
карточка и цвет сломаны».

Поэтому обязательный спутник тайлов — компактный `buildings-index.json`
(id, lon, lat, address, index, year; ≈130 КБ / ≈30 КБ gzip). Пороги цвета и
перцентили считать при экспорте, `breakdown` — из свойств тайла.

## Факт замера (20.11, шаг A, PR #61)

| | Сегодня | PMTiles с breakdown | PMTiles без breakdown |
|---|---|---|---|
| Артефакт зданий | 4,07 МБ / 611 КБ gzip | 2,10 МБ | 761 КБ |
| Тайлы | — | 176 (z12 2, z13 5, z14 12, z15 36, z16 121) | 176 |
| Первый экран (z15, 6–12) | 611 КБ | 77–153 КБ | 28–56 КБ |
| Индекс | — | 263 КБ / 62 КБ gzip | то же |
| Итого первый экран | 611 КБ | 140–215 КБ | 90–120 КБ |

- gzip файла тайлов не даёт выигрыша (внутри уже сжатые MVT).
- `breakdown` — 64% веса тайлов: 2,10 МБ → 761 КБ без него.
- Сборка 3,6–4,1 с; повторный прогон **побайтово идентичен** (sha256).
- 5 контрольных домов совпали по id/index/height/address/year и breakdown.
- Индекс 257 КиБ / 62 КБ gzip (кириллица в адресах).
- `ghcr.io/felt/tippecanoe` недоступен → локальный Dockerfile 2.79.0, ~2 мин.

**Решение:** мигрируем, `breakdown` уходит в `routes/<id>.json` (файл и так
грузится при выборе дома) — это шаг B1. В тайлах остаются id/index/height/
address/year. Цель — первый экран 90–120 КБ вместо 611 КБ.

## Риски

1. **Полная коллекция в памяти.** Митигация — индекс (см. выше), иначе
   регресс карточки/цвета.
2. **Range + service worker.** `sw.js` кладёт всё из `/data/*` в Cache API;
   ответ `206` в `cache.put` бросит исключение. Нужен ранний `return` для
   `*.pmtiles`, хеш в имени файла и smoke-тест `206` в CI.
3. **Тулинг.** tippecanoe из исходников, вложенный `breakdown` (MVT не умеет
   объекты → NDJSON), валидатор ждёт geojson, лимит деплоя 10 минут.

## Порядок работ (3 задачи, каждая — одна сессия)

**A. Пайплайн + артефакты (без изменений на проде).**
`pipeline/build_tiles.py` + `buildings-index.json`, локальный прогон через
Docker/tippecanoe, отчёт: вес pmtiles, число тайлов, вес индекса, 5
контрольных домов совпадают с geojson по id/index/height/address/year.
Прод не меняется: артефакт пока никто не читает.

**B. Клиент на тайлах (первый вертикальный срез).**
`pmtiles@4.5.0`, протокол в `useEffect`, здания из тайлов, поиск/центры/
квинтили/глубокие ссылки — из индекса. POI, красные зоны, подложка остаются
geojson. Флаг отката на geojson.

**C. Гигиена деплоя.**
`*.pmtiles` вне service worker, сборка тайлов в CI (tippecanoe 2.79.0 +
кэш), удаление buildings.geojson из `dist` после генератора страниц,
smoke-тест `206`, фолбэк-путь.

## Критерии приёмки всей миграции

- 3306 зданий экструдируются и кликаются; выбор 5 контрольных домов даёт
  ту же карточку, балл и год.
- `?building=` и `/r/<id>/` работают.
- Квинтили цвета визуально совпадают со скриншотом до миграции.
- Первая загрузка блока зданий < 300 КБ (DevTools).
- Нет ошибок 206/Cache в консоли; валидатор и golden зелёные; деплой < 10 мин.
- Откат: `workflow_dispatch` со старым `data_ref` и geojson-веткой клиента.

## Развилка

1. **Идти по плану A → B → C** — масштабируемо, но это 3 сессии и зависимость
   от недокументированного Range.
2. **Сначала дешёвая гигиена** — слить изохрону в `routes/<id>.json`
   (−3 300 файлов) и добавить индекс поиска; PMTiles позже.
3. **Не делать PMTiles** — 611 КБ gzip на Пресню терпимо; вернуться при
   переходе на второй район.
